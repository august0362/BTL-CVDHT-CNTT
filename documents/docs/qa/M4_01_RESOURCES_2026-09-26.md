# M4-01 — Đo tài nguyên đường web với EMOCA thật + engine thật — 2026-09-26

- **Người đo:** phiên 01_AI, giao việc từ điều phối `btl-e6`. Không sửa mã, không đổi config.
- **Đường đo:** `web.orchestrator.analyze(ảnh, emoca={"mode": "real", "url": "http://127.0.0.1:8765"}, engine_mode="real")`, gọi trong MỘT tiến trình Python (venv `ma3d-web`). Đây đúng là hàm `frontend/app.py` gọi, chỉ không qua trình duyệt/Streamlit.
- **Máy:** Windows + WSL2, GPU RTX 3050 4 GB Laptop (EMOCA); POSTER/MA3D-Net chạy CPU (torch 2.14.0+cpu, `OPENBLAS_NUM_THREADS=1`, `OMP_NUM_THREADS=2`). RAM Windows trống lúc bắt đầu ≈ 1,3 GB; các phiên khác vẫn chạy ⇒ có nhiễu.
- **Ảnh:** 5 ảnh công khai `EMOCA_test_example_data/images/affectnet_test_examples/0000_0000_00 … 0000_0004_00` (224×224). Ảnh chỉ nằm trong scratch, không vào repo.
- **Kịch bản:**
  - server EMOCA đã ấm từ trước (vừa phục vụ 5 yêu cầu của M3-03);
  - tiến trình web MỚI ⇒ **3 lần khởi động** (ảnh 0, 1, 2);
  - rồi **40 lần đo** xoay vòng 5 ảnh (mỗi ảnh 8 lần);
  - sau mỗi lần: đọc `GET /v1/health` (VRAM) và bộ nhớ tiến trình (`K32GetProcessMemoryInfo`).
- **Số thô:** `m4_01_raw.json` trong scratch của phiên (không vào repo). Script tạm `m4_01.py`.

## 4. Đề xuất ngân sách (để GENERAL/CONFIG chốt, không tự đổi config)

| Hạng mục | Đề xuất | Căn cứ |
|---|---|---|
| Phân tích 1 ảnh, hệ đã ấm | **≤ 2,5 s** (p95 đo 1,71 s ⇒ dư ~45 %) | mục 1 |
| Lần đầu sau khi mở web (engine nguội, EMOCA ấm) | ≤ 15 s (đo 10,7 s) | mục 1, khởi động |
| Lần đầu sau khi bật server EMOCA | ≤ 45 s trình duyệt (đo 46,4 s ở web nguội + EMOCA nguội — sát ngưỡng) | E2E 2026-09-25 |
| Timeout web → EMOCA | **giữ 60 s** (`backend/configs/services.yaml` `emoca_svc.timeout_s`). Lần nguội đo 26,9 s | E2E 2026-09-25 |
| RAM tiến trình web (engine thật) | ≤ **1,5 GB** working set (đỉnh đo 1,33 GB) — máy cần ≥ 2 GB RAM trống trước khi bật chế độ Thật | mục 3 |
| VRAM EMOCA | ≤ **2,0 GB** reserved (đo 1,83 GB), giữ ≥ 1 GB trống; `max_concurrent: 1` như hiện tại | mục 2 |

Hai việc giảm lần nguội (chưa làm, chỉ đề xuất):
- gọi làm nóng (warm-up) EMOCA ngay sau khi server sẵn sàng (2 ảnh giả 224×224);
- nạp engine ngay khi web khởi động ở chế độ Thật.

## 5. Chưa đo

- Ảnh lớn / nhiều mặt (VRAM và độ trễ có thể khác nhiều).
- Qua giao diện Streamlit với ≥ 30 lần (thêm thời gian render + truyền ảnh).
- Tải đồng thời (web chỉ xử lý tuần tự).
- Bộ nhớ của `server.py` trong WSL.
